# How File input works

A file input is a field for choosing files from the device to send with a form. It's the browser's own `<input type="file">`: the browser opens the system's file picker and sends the files with the form. FileInput draws the whole field as one button, with its own icon and words over the input, centered: "Choose file", then the chosen file's name or how many. Around it, it's a text field like [Input](?path=/docs/components-input--how-it-works): the same label, help text, error, edge, states, and themes. It adds one thing the browser's input can't do: once a file is chosen, a Remove button empties the field again. This page covers what's different, and links to the Input page for the rest. Every code block is read from the source files when the page loads, so it's always the code that ships, and every demo is the real component.

It uses Base UI's `Field.Root`, `Field.Label`, `Field.Description`, `Field.Error` (through `FieldError`), and `Input`, as Input does, and Base UI's `Button` for Remove. [Base UI](https://base-ui.com), the unstyled library underneath, links the label and help text to the input and handles the ARIA attributes. Base UI has no file component of its own.

The chosen files live in the input's `files` property. The browser also draws a button and words inside the input ("Choose File", "No file chosen"), where no HTML or CSS class reaches them: CSS reaches the button through one pseudo-element, `::file-selector-button`, and the words only through the input's own font and color. FileInput hides both, and shows the names it reads from `files` in its own words instead.

### The component

<Code file="components/FileInput/FileInput.tsx" name="FileInput" />

Some things to notice:

- **The chosen files' names.** The only state is the names of the chosen files, for the field's words and Remove, read from the input, never assumed: once when it first renders (a browser can put files back after the Back button), on every change, and after a form reset. A reset empties the input without a change event, and fires before it empties it, so the count is read on the next turn.
- **Remove** sets the input's value to `""`, the one value a page may give a file input, then fires `input` and `change`, as a person's choice does, so `onChange`, `onFilesChange`, form libraries, and anything else listening hear it. Then focus goes back to the input.
- **A file dropped on Remove** goes to the field. Remove sits over the field's end, so a file dragged there lands on the button, not the input, and the browser would otherwise open the file in the tab and leave the form.

The browser draws a "Choose File" button and words beside it ("No file chosen") inside the input, worded differently in every browser, and won't center them. So all of it is drawn at size 0, and the field draws its own words over it instead. Making it transparent would also hide it, but Windows high contrast themes replace every text color, and it would come back. Screen readers still hear the browser's words.

Hovering or pressing anywhere on the field fills it, as it would a secondary button, since the whole field opens the picker. Browsers count hovering the label as hovering the input, so the rule leaves the field alone then: clicking the label only focuses the field.

## Keyboard, screen readers, and forms

**Keyboard.** It's the browser's own file input: Tab moves to it, and Enter or Space opens the system's file picker, as a click anywhere on the field does. While a file is chosen, Remove is the next Tab stop; Enter or Space empties the field and moves focus back to it. A disabled field, and its Remove, are skipped by Tab.

**Screen readers** announce the label as its name, that it's a button (the words depend on the screen reader and browser), the browser's own status ("No file chosen", the file's name, or how many, in the browser's language), then the description and any error. The words drawn on the field are hidden from them, so nothing is read twice.

**Browsers** all look the same: the words on the field are FileInput's, not the browser's (Chrome's "Choose File", Firefox's "Browse…"). They're English for now (see `docs/revisit.md`).
