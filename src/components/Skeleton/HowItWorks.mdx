# How Skeleton works

A skeleton is gray shapes that stand in for content while it loads: an avatar and two lines of text for each row of a list, say. This page walks through the real code underneath it: the HTML it renders, how a skeleton tells screen readers what's loading, and how the CSS draws, sizes, and pulses the shapes. Every code block is read from the source files when the page loads, so it's always the code that ships, and the demo is the real component.

## What it's made of

Skeleton doesn't use [Base UI](https://base-ui.com), the library most components are built on: Base UI has no skeleton, and a skeleton has no keyboard use or focus for a library to handle. It's two components, a few elements, and the same small piece of timing code Spinner uses.

## What screen readers hear

Screen readers can't see gray shapes, so every shape is hidden from them, and the skeleton says what's loading in words instead: its `label`, "Loading applications…". It's announced exactly the way Spinner's label is, and [How Spinner works](?path=/docs/components-spinner--how-it-works) explains why in full. In short: a screen reader announces a `role="status"` region when its words change, and many miss words that arrive together with the region, so the region starts empty and gets the words a moment later. The other copy of the label, in the HTML from the start, covers a page read before JavaScript runs. Once JavaScript runs, it's hidden, so the words are heard once.

Unlike Spinner, both copies are visually hidden: a skeleton shows shapes, not words.

There's no `aria-busy`, the attribute meant to say an area is still loading. Only one screen reader (JAWS) supports it, and it can hold back what the area announces until it's no longer busy.

## The CSS, rule by rule

### A shape

A gray `track` fill with a transparent edge. In Windows' forced colors mode, the browser removes every fill but draws the edge in the text color, so each shape still shows as an outline. A box is as wide as its container (in a flex row, which has no width to give it, add `flex-1` or a width class); its height, and a circle's size, come from Tailwind classes in your markup. With none, they're one line of text tall (`1lh`).

<Code file="components/Skeleton/skeleton.css" name=".skeleton-item" />

<Code file="components/Skeleton/skeleton.css" name='.skeleton-item[data-shape="circle"]' />

### Lines of text

A text shape has no fill of its own: its lines are the shapes. Each takes one line of the text around it (`1lh`, the line height), with a bar as tall as that text's letters (`1em`, the font size) in the middle, so separate lines read as separate. Give the shape the text style of the text it stands in for, and its lines match that text exactly. The last of several lines is shorter, the way a paragraph ends.

### The pulse

Every shape fades to half and back, once every two loops: 1.4 seconds, or 3.2 with reduced motion. Reduced motion slows it rather than stopping it, because a loading indicator that stops looks like something broke. It only animates `opacity`, as the motion rules ask, and shapes that appear together pulse together.

### The delay

Like Spinner's: the skeleton is invisible until `--skeleton-delay` is over, then fades in. It's CSS, so it works before JavaScript runs.

<Code file="components/Skeleton/skeleton.css" name=".skeleton[data-delayed]" />

### Hot dog mode

Light gray on mustard is faint, so every shape gets a thin ink edge. Not the thick edge other hot dog components get: that would make placeholders look like real controls.

<Code file="components/Skeleton/skeleton.css" name='[data-theme="hotdog"] .skeleton-item' />

### No touch, density, focus, or hover rules

Nothing about a skeleton can be pressed or focused, so it has no hit area, no focus ring, and nothing that changes with a touch screen or compact density.

## How it's tested

The unit tests check the HTML before and after JavaScript runs (including that it hydrates without a mismatch), when the label is announced with and without a delay, that every shape is hidden from screen readers, the shapes and `lines`, refs, and the props types. The stories check what needs real CSS: that text lines are as tall as their text style, the shorter last line, box and circle sizes, the pulse's speed with and without reduced motion, the delay's fade, and hot dog's ink edge.
