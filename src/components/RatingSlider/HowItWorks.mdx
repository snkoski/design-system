# How RatingSlider works

A rating slider is a row of stars that works as a slider: drag across it, click anywhere on it, or use the arrow keys, and the stars fill to the value, in whole, half, or quarter stars. Underneath, it's Base UI's Slider: one `<input type="range">` holds the value, and the stars are only a drawing of it. [Rating's How it works page](?path=/docs/components-rating--how-it-works) covers the star and the shared pieces; this page covers what's different.

## 2. The component

<Code file="components/RatingSlider/RatingSlider.tsx" name="RatingSlider" />

In order, it:

- Checks it has a name and a usable `max` (5 if not), as Rating does.
- Gets its value from `useResettableValue`, so it always gives Base UI the value; 0 and `null` both mean no rating.
- Snaps the value to the nearest step and into range, so the stars, the input, and the form agree, and warns in development when the page's value wasn't on a step.
- Works out the hover preview from the pointer: the control's box minus its padding, as Base UI measures a press, rounded to the step. Only for a mouse or pen, not while a button is held, and cleared by a key press until the pointer moves again.
- Cancels every change while read-only, since Base UI's slider has no read-only state, and reports changes with `null` for 0 otherwise.
- Sets your `id` and `aria-readonly` on the input itself (Base UI passes only a few props to it), and focuses the input when the label is clicked, since Base UI's label looks the input up by the id it gave it.
- Wraps the slider in a left-to-right `DirectionProvider` and puts `dir="ltr"` on the stars, so Base UI's pointer math and keys match the drawing in a right-to-left page.

## 4. Following a form reset

Base UI's slider keeps its value through a form reset, because React keeps the input's `value` attribute in step with it. `useResettableValue` listens for the form's `reset` and puts an uncontrolled slider back to `defaultValue`; a controlled one keeps `value`.

## 5. The CSS

The frame has a width of its own, the no-rating strip and the stars at `choice-row` each, and shrinks to fit a narrower parent. It's the container the cell is measured in, so the stars narrow with it.

<Code file="components/RatingSlider/rating-slider.css" name=".rating-slider__frame" />

Base UI maps a press across the control's content box and rounds to the nearest step. The padding starts the content box half a step before the stars and ends it half a step before their end, so a press anywhere on a step's slice fills to the end of that slice, and anything left of the stars is 0.

## 6. The color

The `color` prop is turned into what the wrapper renders by a helper Rating and RatingSlider share. A keyword (`"gold"`, the default, or `"brand"`, ignoring case and spaces) becomes `data-color`. Anything else is a CSS color, set inline as `--rating-color` and used as given in every theme, with `data-color="custom"`. In the browser it asks `CSS.supports` whether the value is a color, and warns in development if not; the CSS-wide keywords such as `inherit` warn too, since on a variable they reset it rather than color anything, and so does `transparent`, which hides the stars.

<Code file="internal/ratingColor.ts" name="ratingColor" />

The component's CSS sets `--rating-color` on the wrapper from the matching token: `rating-gold` (deep amber in light, bright gold in dark, ketchup in hot dog) or `rating-brand`. Both are checked for 3:1 against the page, cards, and tinted panels in every theme. An inline `--rating-color` beats both rules. Because the wrapper sets the variable itself, a parent can't: the prop is the way in, and a brand file changes `--rating-gold` or `--rating-brand` instead.
